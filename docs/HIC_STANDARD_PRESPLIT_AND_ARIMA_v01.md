# Standard diffHic mapper and future cocktail libraries

On 13 October 2026 the user authorized the standard diffHic presplit mapper as a replacement candidate for the unavailable `presplit_map_t32.py`. The custom helper remains unrecovered. The suffix probably denotes 32 threads: the recovered notebook requests 32 CPUs, and the upstream mapper accepts `--cmd "bowtie2 -p 32"`. This is an inference, not proof of the missing modifications.

The unchanged public source is archived in `historical/upstream_diffhic_standard`, pinned to SmythLab/diffHic commit `11920f8c763501714c16c75d2faff14734fa7edd`. Its SHA-256 is `571ac61c65d068c22ab8b94a3a87a9f7aee8ec570e3fb5a716303fbb2a31b09a`. The repository DESCRIPTION identifies diffHic 1.45.0 and GPL-3. This is the public source revision, not the historical custom runtime or the current installed R version. Original Python 3.8.8 and its complete dependency identity are not recovered.

The selected route is explicit: `stage=raw_prepare`, `hic_alignment_mode=diffhic_presplit_standard_compat`, a pinned `hic_raw_container`, paired FASTQs and a Bowtie2 index. For the in-house MboI libraries, the restriction motif is `GATC`, and the recorded filled-in ligation signature is `GATCGATC`. Restriction motif and ligation signature are separate parameters; setting the signature to `GATC` would change splitting.

`bin/prepare_presplit_mapper.py` verifies the source identity and creates a task-local adapter with an audit listing every replacement. It fixes an upstream assignment that sets mate-2 only on the 5′ segment, marks 3′ segments secondary to follow the documented diffHic BAM contract, replaces obsolete text-open mode, decodes subprocess errors and drains subprocess stderr before waiting. Signature matching, split position and alignment options remain the upstream algorithm. The original upstream file is never edited. These changes do not authenticate equivalence to `_t32`.

The candidate container pins Python 3.9.18, Biopython 1.83, pysam 0.22.1, NumPy 1.26.4, Cutadapt 4.8, Bowtie2 2.5.3, Picard 3.1.1 and samtools 1.22.1. Biopython/pysam versions are new candidate choices, not asserted historical versions. The process synchronizes mate information, marks duplicates with `REMOVE_DUPLICATES=false`, then sorts by name. It currently emits a BAM checkpoint; A separate hic_diffhic_counts stage uses name-sorted BAM checkpoints, cutGenome, duplicate-aware preparePairs, pruning, squareCounts and joint csaw loess offsets. Its current-library container snapshots diffHic 1.40.0 under R 4.5.1. Full-cohort equivalence and a validated path from these counts to STARE remain outstanding. Preserved cooler/corrected-H5 routes continue to carry the existing GRN qualification.

The [diffHic guide](https://bioconductor.uib.no/packages/3.23/bioc/vignettes/diffHic/inst/doc/diffHicUsersGuide.pdf), section 2, explains the 5′-alignment requirement, signature splitting, mate synchronization, duplicate marking, name-sorted input and hard clipping. The linked PDF identifies itself as the October 2017 guide for diffHic 1.9.8, despite its current Bioconductor URL. Retain that distinction when citing it.

## Arima and other enzyme cocktails

The user supplied Aaron Lun's Bioconductor forum explanation: presplit mapping can indiscriminately split at chance matches when several short signatures are present. A map-first, split-unmapped strategy can reduce this problem. This quoted forum account is recorded as user-supplied attribution; the exact thread URL was not supplied, and live access to the support site is blocked by robots.txt. It is not presented as independently recovered forum evidence.

For a future cocktail dataset, assess and pin either [HiC-Pro](https://github.com/nservant/HiC-Pro) or the [Arima mapping pipeline](https://github.com/ArimaGenomics/mapping_pipeline), including its exact kit/version, alignment strategy, reference and digestion settings. These are future method candidates, not installed or validated alternatives in this release. Do not concatenate signatures into the single-signature presplit argument. The current standard-route guard rejects multiple restriction motifs.

Before feeding an externally prepared BAM into diffHic, verify that mates share the same QNAME and that the informative 5′ alignment of each read is present. If retaining split segments for diagnostics, verify common names, hard clipping and secondary 3′ segments. Synchronize mate fields, mark duplicates and name-sort the BAM. Merely producing a BAM with either pipeline does not establish this compatibility. The guide independently supports the hard-clipping/5′/name-sort requirements; the secondary-segment wording here follows the user-supplied forum advice.

The recovered notebook uses `cutGenome(..., "GATC", 4)`, `preparePairs(dedup=TRUE, minq=10, chim.dist=1000)` and `prunePairs(max.frag=800, min.inward=1000, min.outward=1000)`. These are provenance for the original single-enzyme experiment, not universal defaults for Arima libraries. Multi-enzyme fragmentation and counting need a separately labelled protocol.

## Counting boundary

The standalone counting stage exports InteractionSet RDS, raw counts, log offsets and QC for each requested resolution. It orders libraries by samplesheet identity. Its synthetic two-library fixture deliberately reuses the same eight-pair BAM and overrides pruning distances for the short synthetic interactions; it does not represent independent biological replicates.

For restriction-fragment Hi-C, squareCounts rounds bin boundaries to restriction sites. Thus a requested width is a nominal binning resolution, and these output intervals are not fixed-grid cooler bins. Preserve the actual intervals and do not silently feed them through the existing fixed-grid corrected-H5/STARE guard. This behavior is documented in the [diffHic reference manual](https://bioconductor.org/packages/release/bioc/manuals/diffHic/man/diffHic.pdf), squareCounts Details. The first validator incorrectly assumed fixed-grid boundaries and failed; the revised check verifies restriction-fragment boundaries and table/RDS identity.
